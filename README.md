# Проект 2. Cashback Merge

Мини-игра в духе 2048 на поле `4x4`. На поле появляются плитки с кэшбэком,
две одинаковые объединяются в следующую:

```text
1% + 1% = 2%    2% + 2% = 4%    ...    16% + 16% = 32%
```

У игрока ограниченное число ходов, цель — собрать максимальный кэшбэк.

Но у проекта есть второй, продуктовый слой. По итоговой плитке начисляется
награда, и эта награда стоит компании денег. Поэтому максимальную награду
должна получать ограниченная доля игроков — например, не больше `20%`.
Проверяется это симуляцией на тысячах «игроков» до запуска акции.

Задание разбито на три merge request'а. Делай их по очереди.

### Текущий статус: MR2 (Движок ходов)

**MR1 (Фундамент):**
* **Игровая модель:** реализованы классы Board (поддерживает динамический размер), Tile и GameState. Настроено корректное сравнение состояний поля через equals и Arrays.deepHashCode.
* **Конфигурация (Jackson):** загрузка настроек из JSON (CampaignConfig) со строгой Fail-Fast валидацией (сумма вероятностей = 1, лимит ходов > 0).
* **Генератор состояний:** реализован алгоритм взвешенного выбора (рулетка) с точной математикой на BigDecimal. Воспроизводимость стартового поля гарантируется через seed.
* **Тесты:** проходят обязательные тесты валидации (ConfigValidationTest) и проверки сида (SeedTest).

**MR2 (Движок ходов):**
* **Физика поля:** реализован класс `GameEngine`, который сдвигает и объединяет плитки по правилам 2048 во всех четырех направлениях (UP, DOWN, LEFT, RIGHT).
* **Игровой цикл:** метод `applyMove` корректно обрабатывает ходы — лимит тратится и новая плитка спавнится только в том случае, если поле изменилось.
* **Архитектура:** применен паттерн Dependency Injection — движок получает зависимости (`CampaignConfig`, `Random`, `GameInitializer`) через конструктор, сохраняя чистоту бизнес-логики.
* **Тесты:** успешно реализованы обязательные проверки слияния линий (`MergeRulesTest`) и механики траты ходов, очков и состояний игры (`MoveEngineTest`).
